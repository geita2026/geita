## 3. Trade Promotion re-homed to module 1 (DB only)

`config/navigation.php` was not the gatekeeper here: the sidebar is **DB-driven** —
`resources/views/layouts/sidebar.blade.php` queries `level_one_menuses` filtered by
`session('moduleNo')`, and nothing sets `moduleNo=2` any more, so the whole module-2 block
was unreachable.

Changed in `mis_update`:

```sql
update level_one_menuses set moduleNo=1
where level_one_common_name='Trade Promotion' and moduleNo=2;
```

- Row `8cc7e1ed-f20f-42b6-bea9-eef26eacb5ab`, 1 row affected. No code change; routes,
  controllers, views and permissions untouched.
- Backup before the update: `/tmp/geita-backups/menus-before-trade-promotion-rehome-2026-11-22.sql`
- Sidebar now returns 22 module-1 groups including Trade Promotion; Super Admin passes its
  `level_one_gate_name` (`Manage EventParticipants`). `SAC Officer` and `Chief Accountant (CA)`
  already hold `Manage EventParticipants` + `Manage PromotionEvents`, so they see it too.
- `/promotion_events` and `/event_participants` → 302 (login redirect), not 404.
